# 排水底图厘米→分米保流向转换（Flask + SQLite）

## 1. 背景

旧排水程序只读取**整数分米**高程，对厘米测量值逐格取整。缓坡上相邻两格的厘米高差
可能只有 3–7 cm，取整后被压成同一分米值，原本的下坡变成平地、流向丢失或凭空新增，
且无法处理并列最低与坑点（无下坡）。

本服务接收**整数厘米高程 CSV**（≤ 32×32 格）与**最大允许误差 E（厘米）**，
求解一份**整数分米 CSV**，保证：

1. 每格 `|10·D[r,c] − H[r,c]| ≤ E`；
2. 转换前后每格流向完全一致；
3. 关键格（如沟口）可锁定分米值，测绘更正上传时沿用锁定重新求解；
4. 误差限内无解时不覆盖上一份可下载底图，并给出**最小可行误差**；
   放宽误差仍无解时，明确报告锁定值与流向不可兼得。

### 流向定义（严格按需求）

> 每格的流向 = 四邻（上/下/左/右，不含对角）中**最低且严格低于本格**的**所有**邻格。

* 多个邻格并列最低 → 全部保留（多流向）；
* 没有严格更低的邻格 → 流向为空（坑点/无下坡），转换后仍须为空。

## 2. 算法

把所有要求写成整数差分约束 `D[v] − D[u] ≤ w`：

| 要求 | 约束 |
|---|---|
| 每格误差 ≤ E | 每格绝对取值区间 `[⌈(H−E)/10⌉, ⌊(H+E)/10⌋]`；锁定格区间收缩为单值 |
| H 的下坡邻格 v（H[v]<H[u]）保持下坡 | `D[v] ≤ D[u] − 1`（边 u→v，权 −1） |
| 等高/更高邻格不得变成下坡 | `D[v] ≥ D[u]`（边 v→u，权 0） |
| 并列最低邻格之间 | 分米值相等（两条 0 权边） |
| 最低邻格 vs 其他下坡邻格 | 最低者严格更低（权 −1 边） |

* 以上界为 SPFA 初始距离（隐式 0 权超级源），求逐点最大解并检测负环；
* 出现负环，或最大解仍低于某格下界 → 该 E 下不可行；
* 对 E 二分得到**最小可行误差**（上界取一个必然容纳全部排序需求的大值，
  若大误差仍无解，则判定为锁定与流向的硬冲突）；
* 每个成功解在返回前都会再次做完整自检（误差、锁定、逐格流向集合相等）。

实现见 `app/solver.py`，32×32 随机底图完整转换（含二分）实测约 0.4 s。

## 3. 数据与保留语义（SQLite）

* `projects`：转换任务（固定行列尺寸）；
* `locks`：分米锁定值（沟口等），更正与重转时自动沿用；
* `snapshots`：每次转换尝试。成功存分米格网与逐格误差；失败只存状态
  （`tight` 误差过紧 / `conflict` 硬冲突），`grid_dm` 为 NULL。

**可下载底图永远取最新一条 `status='ok'` 的快照**：失败尝试（包括失败的测绘更正）
不会覆盖它，锁定值也不会被清除。


## 5. 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库持久化在宿主 `app/local_data/drainage.db`，容器重建不丢数据。
健康检查：`GET /healthz`。

### 本地直接运行（无 Docker 时）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m app.serve          # 工作目录为仓库根；默认 0.0.0.0:8000
```

### 测试

```bash
python -m unittest discover -s tests -v
```

## 6. 网页演示路径（用 sample/ 数据）

1. 首页新建任务，上传 `sample/slope_cm.csv`，误差填 **9** → 转换成功，
   页面并列出厘米/分米格网与流向箭头（`·` 为无下坡，多箭头为并列）；
   该底图最小可行误差为 7 cm。
2. 误差改填 **0** 重转 → 提示“最小可行误差为 7 cm”，下载按钮给出的仍是旧底图。
3. 锁定沟口（第 6 行第 6 列 = 8 dm）后重转 → 锁定格高亮 `L`，值被严格遵守。
4. 上传 `sample/correction_cm.csv`（同尺寸测绘更正）→ 沿用锁定转换成功。
5. 制造硬冲突：把 (6,6) 锁 17、(6,5) 锁 16（与原高低关系颠倒），
   即使误差放到 100000 也提示“锁定值与流向要求无法同时满足”。
6. “下载当前分米 CSV”得到整数分米结果；转换历史保留全部尝试与状态。

## 7. 已验证的关键行为（自测，26 项测试全过）

* CSV 校验：非整数、缺列、空文件、超过 32×32 均被拒绝；
* 流向：并列最低全保留、无下坡保持为空、对角格不参与；
* 任意可行解逐格误差 ≤ E、锁定值精确满足、转换前后流向集合逐格相等；
* 0 误差仅在全 10 倍数且排序兼容时可行，否则给出最小可行误差；
* 随机 30 组底图 + 32×32 满尺寸底图不变量成立；负高程可解；
* 误差过紧：失败提示最小误差，上一份成功底图与锁定原样保留；
* 硬冲突：任意放宽误差均无解并明确提示；
* 测绘更正：尺寸不符被拒；失败更正只新增失败记录，不改变可下载底图。

## 8. 限制与未完成事项

* 本环境未安装 Docker 守护进程，镜像构建与 `docker compose` 未做真机验证，
  仅对容器内将运行的同一入口（`python -m app.serve` + waitress）做了本地实测；
  Dockerfile/compose 语法已人工核对。
* SPFA 对 32×32（≤1024 节点）实测足够快；若将来放宽尺寸上限，
  建议改用 Bellman–Ford 之外的专用差分约束实现并加超时保护。
* 无用户体系，任务对所有访问者可见；SECRET_KEY 走环境变量，生产部署需覆盖默认值。
* CSV 仅支持 UTF-8（含 BOM）整数文本，未支持浮点/空格分隔等变体。
