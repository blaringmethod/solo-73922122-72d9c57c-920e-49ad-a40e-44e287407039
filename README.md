# 排水底图厘米→分米保流向转换（Flask + SQLite）

## 1. 背景

旧排水程序只读取**整数分米**高程，对厘米测量值逐格取整。缓坡上相邻两格的厘米高差
可能只有 3–7 cm，取整后被压成同一分米值，原本的下坡变成平地、流向丢失或凭空新增，
且无法处理并列最低与坑点（无下坡）。

本服务接收**整数厘米高程 CSV**（≤ 32×32 格）与**最大允许误差 E（厘米）**，
求解一份**整数分米 CSV**，保证：

1. 每格 `|10·D[r,c] − H[r,c]| ≤ E`；
2. 转换前后每格流向完全一致；
3. 关键格（如沟口）可锁定分米值，测绘更正上传时沿用锁定重新求解；
4. 误差限内无解时不覆盖上一份可下载底图，并给出**最小可行误差**；
   放宽误差仍无解时，明确报告锁定值与流向不可兼得。

### 流向定义（严格按需求）

> 每格的流向 = 四邻（上/下/左/右，不含对角）中**最低且严格低于本格**的**所有**邻格。

* 多个邻格并列最低 → 全部保留（多流向）；
* 没有严格更低的邻格 → 流向为空（坑点/无下坡），转换后仍须为空。

## 2. 算法

把所有要求写成整数差分约束 `D[v] − D[u] ≤ w`：

| 要求 | 约束 |
|---|---|
| 每格误差 ≤ E | 每格绝对取值区间 `[⌈(H−E)/10⌉, ⌊(H+E)/10⌋]`；锁定格区间收缩为单值 |
| H 的下坡邻格 v（H[v]<H[u]）保持下坡 | `D[v] ≤ D[u] − 1`（边 u→v，权 −1） |
| 等高/更高邻格不得变成下坡 | `D[v] ≥ D[u]`（边 v→u，权 0） |
| 并列最低邻格之间 | 分米值相等 |
| 最低邻格 vs 其他下坡邻格 | 最低者严格更低（权 −1 边） |

约束图是**类 DAG**：0 权边只连接等高格，用并查集缩成“必须同值”分量后，
剩余边全部从高分量指向低分量。因此：

* **给定误差限**：按高程从高到低做一次拓扑扫描即得逐点最大可行解，
  再校验下界；不再用 SPFA 反复松弛。
* **最小可行误差**：一次“11 标签”扫描（E 的 10 种个位余数 + 1 个锁定
  常数标签）后，一遍 O(10·格数) 汇总即**精确**得到最小整数厘米误差：
  把 E 写成 `10k+e`，非锁定格上下界对 k 线性，约束可解出 `k` 的闭式
  下界；锁定格用常数标签传播，锁定值离测绘高程再远也直接由其误差
  `|10L−H|` 进入结果。**不对多个候选误差逐个检查全图**。
* 锁定互相矛盾的固定值会让常数标签低于锁定自身，直接判定为“放宽也无解”。
* 每个成功解在返回前仍做完整自检（误差、锁定、逐格流向集合相等）。

### 复用与更正

* 流向约束图按**厘米格网内容**缓存在进程内；同一份格网反复改误差限、
  增删/修改锁定都复用同一张图，只重跑标签扫描。
* 新建、重转、更正走同一套求解路径；更正上传使用**新的厘米高程**，
  即使流向结构与原图相同，误差也一定按新高程重算。

实现见 `app/solver.py`。32×32 随机底图：冷启动完整转换（建图 + 最小误差
+ 求解 + 自检）约 45 ms，改锁后重新试算约 20–35 ms；旧二分实现约 320 ms。

## 3. 数据与保留语义（SQLite）

* `projects`：转换任务（固定行列尺寸）；
* `locks`：分米锁定值（沟口等），更正与重转时自动沿用；
* `snapshots`：每次转换尝试。成功存分米格网与逐格误差；失败只存状态
  （`tight` 误差过紧 / `conflict` 硬冲突），`grid_dm` 为 NULL。

**可下载底图永远取最新一条 `status='ok'` 的快照**：失败尝试（包括失败的测绘更正）
不会覆盖它，锁定值也不会被清除。

## 4. 目录结构

```
app/
  solver.py            差分约束建模、类 DAG 拓扑扫描、精确最小误差、流向与自检
  app.py               Flask 路由与 SQLite 持久化
  serve.py             容器入口（建表 + waitress）
  templates/ static/   页面（任务列表、格网对照、锁定、更正、历史）
sample/
  slope_cm.csv         示例厘米底图（含并列、坑点；旧程序取整会破坏流向）
  correction_cm.csv    同尺寸测绘更正示例
tests/
  test_solver.py       求解器单元/随机/边界/精确最小误差/扫描次数测试
  test_web.py          Flask + SQLite 端到端测试（含底图页试算）
scripts/
  bench_min_error.py   两组同流向结构、不同高差格网的最小误差检查次数对比
Dockerfile  docker-compose.yml  requirements.txt
```

## 5. 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库持久化在宿主 `app/local_data/drainage.db`，容器重建不丢数据。
健康检查：`GET /healthz`。

### 本地直接运行（无 Docker 时）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m app.serve          # 工作目录为仓库根；默认 0.0.0.0:8000
```

### 测试

```bash
python -m unittest discover -s tests -v
```

## 6. 网页演示路径（用 sample/ 数据）

1. 首页新建任务，上传 `sample/slope_cm.csv`，误差填 **9** → 转换成功，
   页面顶部“误差试算”立即显示该底图最小可行误差 **7 cm**（无需再次转换），
   并列出厘米/分米格网与流向箭头（`·` 为无下坡，多箭头为并列）。
2. 误差改填 **0** 重转 → 提示“最小可行误差为 7 cm”，下载按钮给出的仍是旧底图。
3. 锁定沟口（第 6 行第 6 列 = 8 dm，该格测绘高程 75 cm）后点
   **“改锁后立即试算”** → 不产生快照，直接给出当前锁定下的最小误差 7 cm；
   再重转 → 锁定格高亮 `L`。
4. 把 (1,1) 改成 100 dm（远离测绘值 317 cm）后试算 → 精确提示 **683 cm**；
   用 682 cm 重转提示误差不足，用 683 cm 重转成功。删除该锁后试算恢复 7 cm。
5. 上传 `sample/correction_cm.csv`（同尺寸测绘更正）→ 沿用锁定转换成功。
6. 制造硬冲突：把 (6,6) 锁 17、(6,5) 锁 16（与原高低关系颠倒），
   试算与重转都提示“放宽误差也无解”。
7. “下载当前分米 CSV”得到整数分米结果；转换历史保留全部尝试与状态，
   失败的更正不会覆盖上一份可下载底图。

## 7. 已验证的关键行为（自测，37 项测试全过）

* CSV 校验：非整数、缺列、空文件、超过 32×32 均被拒绝；
* 流向：并列最低全保留、无下坡保持为空、对角格不参与；
* 任意可行解逐格误差 ≤ E、锁定值精确满足、转换前后流向集合逐格相等；
* 0 误差仅在全 10 倍数且排序兼容时可行，否则给出最小可行误差；
* 随机底图 + 32×32 满尺寸底图不变量成立；负高程可解；
* 精确最小误差：与逐候选顺序搜索在随机/边界用例上完全一致；
* 远端锁定：锁 100 dm 时精确报 683 cm，682 不足、683 可行；
* 硬冲突：任意放宽误差均无解并明确提示；
* 改锁复用同一约束图；同一份格网再次试算只做 1 次全图扫描；
* 更正后即使流向结构相同，误差按新厘米高程重算；
* 底图页试算不产生快照、不改变可下载底图；
* 测绘更正：尺寸不符被拒；失败更正只新增失败记录，下载/重转仍用原工作底图。

### 最小误差全图检查次数对比

运行 `python3 scripts/bench_min_error.py`（A 为原始高差，B 为 `3·h+37`，
流向结构相同、高差不同）：

| 格网 | 锁定 | 逐候选检查（旧） | 一次扫描（新） | 最小误差 |
|---|---|---:|---:|---:|
| A 原始高差 | 无 | 13 | 1 | 7 cm |
| A 原始高差 | (1,1)=33 dm | 13 | 1 | 13 cm |
| B ×3+37 高差放大 | 无 | 15 | 1 | 5 cm |
| B ×3+37 高差放大 | (1,1)=33 dm | 15 | 1 | 658 cm |

## 8. 限制与未完成事项

* 本环境未安装 Docker 守护进程，镜像构建与 `docker compose` 未做真机验证，
  仅对容器内将运行的同一入口（`python -m app.serve` + waitress）做了本地实测；
  Dockerfile/compose 已人工核对，交付后仍需在有 Docker 的机器上跑一次
  `docker compose up --build` 复核。
* 约束图缓存是**进程内**的（按厘米格网内容，最多 32 份），重启即清空；
  多进程部署时各进程各建一份，不影响正确性。
* 无用户体系，任务对所有访问者可见；SECRET_KEY 走环境变量，生产部署需覆盖默认值。
* CSV 仅支持 UTF-8（含 BOM）整数文本，未支持浮点/空格分隔等变体。
